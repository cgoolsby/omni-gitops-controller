# Prompt 10 — Add `observedGeneration` to Status

## Context

`observedGeneration` is the standard Kubernetes controller convention for tracking whether the current status reflects the current spec. It is set to `metadata.generation` at the end of each successful reconcile. Automation and tooling (Flux, ArgoCD, `kubectl wait`) use it to determine if the status is fresh.

Without it:
- A user can't tell if `status.ready: true` reflects the spec they just applied or a previous version.
- `kubectl wait --for=condition=Ready` may return immediately on stale status.
- The Flux `dependsOn` mechanism cannot reliably gate on `OmniCluster` readiness.

---

## What to Do

### 1. Add `ObservedGeneration` to `OmniClusterStatus`

In `api/v1alpha1/types.go`:

```go
type OmniClusterStatus struct {
    // ObservedGeneration is the .metadata.generation that was last processed by the controller.
    // +optional
    ObservedGeneration int64 `json:"observedGeneration,omitempty"`

    // ... existing fields ...
}
```

### 2. Set it in the reconcile loop

In `omnicluster_controller.go`, just before `r.Status().Update(ctx, cluster)`:

```go
cluster.Status.ObservedGeneration = cluster.Generation
```

This must be set **only on the success path** (not in `setFailure`), so that `observedGeneration < metadata.generation` is a reliable signal that the controller hasn't finished processing the current spec.

Actually, consider setting it in `setFailure` too with the current generation, since the controller *did* observe this generation — it just failed to reconcile it. This is consistent with how most controllers handle it. Either approach is defensible; pick one and document it.

### 3. Regenerate the CRD

After modifying `types.go`, run:

```bash
controller-gen crd:generateEmbeddedObjectMeta=true \
  paths="./api/..." \
  output:crd:artifacts:config=config/crd/bases
```

Then copy the updated CRD to `charts/omni-gitops-controller/crds/` if that file is not auto-generated by the Helm chart build process (check whether it is symlinked or copied).

### 4. Update `deepcopy`

Run:

```bash
controller-gen object:headerFile="hack/boilerplate.go.txt" paths="./api/..."
```

Or if there's no boilerplate file:

```bash
controller-gen object paths="./api/..."
```

This regenerates `api/v1alpha1/zz_generated.deepcopy.go`.

---

## Verification

```bash
kubectl get omnicluster <name> -n omni-gitops-system -o jsonpath='{.status.observedGeneration}'
# Should return a number equal to:
kubectl get omnicluster <name> -n omni-gitops-system -o jsonpath='{.metadata.generation}'
```

After editing the spec (which increments `metadata.generation`), `observedGeneration` should lag by 1 until the next reconcile completes.
